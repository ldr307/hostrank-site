Who this plan suits

DigitalOcean Basic 1 GiB fits a developer who wants a self-managed Cloud VPS for a modest workload: a personal project, a webhook receiver, a small REST or JSON API, or a staging copy of an app. With 1 GiB of RAM and 25 GiB SSD of storage, it is a starting point for one service rather than a stack of databases, workers and caches all competing for memory.

Because this is a self-managed server, you get SSH access and root-level control, and you choose the operating system packages, the web server and the runtime. That flexibility suits someone comfortable on the command line. If you would rather not handle patching, firewall rules and backups yourself, a managed hosting product is a better match than any VPS.

What the plan lists

The plan lists 1 GiB of RAM and 25 GiB SSD of storage. Its single listed feature is "Flat monthly price (no intro discount)".

If your API depends on a certain amount of outbound traffic or on provider-side backups, confirm those details on the provider's pricing page before signing up.

What a self-managed server needs from you

SSH access: log in with SSH keys instead of passwords, create a regular user with sudo rights for daily work, and limit direct root logins. This step alone removes a large share of automated login attempts against a public server.

Updates: a fresh server image ages quickly. Apply operating system updates right after the first login and enable automatic security updates so patches keep arriving while you focus on the project.

Firewall: allow only what the service needs, typically SSH, HTTP and HTTPS, and keep database and internal application services closed to the public internet. Put your API behind a reverse proxy such as Nginx rather than exposing the app server directly.

Backups: plan them before you need them. Since the data does not confirm provider-side backups for this plan, decide whether to add a provider option after checking it, export your database and files on a schedule, and store copies off the server. Test a restore at least once so you know the backups actually work.

Practical setup guide

  1. STEP 1Create the server and lock down SSH

    Create the server, choose a Linux distribution you know, add your SSH public key, and note the server's IP address. Log in over SSH, create a regular user with sudo rights, and turn off password logins once key-based access works. Apply all pending operating system updates and enable automatic security updates.

  2. STEP 2Turn on a firewall

    Allow only SSH, HTTP and HTTPS through the firewall and keep everything else closed, including your database and the port your app server listens on internally. Confirm you can still reach the server over SSH before closing your current session.

  3. STEP 3Deploy the app behind Nginx and test it

    Install your runtime and Nginx, run your API as a system service, and configure Nginx as a reverse proxy in front of it. Test the service against the server's IP address until it responds correctly. Only move on to DNS once the new setup is working.

  4. STEP 4Point the domain and issue a certificate

    Create A and AAAA records for your domain that point at the server's IP addresses, then confirm the change has reached the resolver you use with this command, replacing example.com with your own domain: dig +short A example.com. Once it returns your server's IP, install Certbot and request a Let's Encrypt certificate for Nginx, again replacing the example domains with your own: sudo certbot --nginx -d example.com -d www.example.com.

  5. STEP 5Set up backups and note the billing details

    Schedule regular exports of your database and application files and copy them off the server, then test a restore. Since provider-side backups are not confirmed for this plan, check that option separately if you want it. Record the billing term and any prepayment requirement shown at checkout so the account stays in good standing.

Frequently asked questions

  • Is DigitalOcean Basic 1 GiB enough for a small API?

    It lists 1 GiB of RAM and 25 GiB SSD of storage, which can work for a single lightweight service. Whether it is enough depends on your runtime, your database and your traffic. The CPU allocation and bandwidth allowance are not listed, so check those before relying on it for production traffic.

  • Does the price go up at renewal?

    No. The renewal price is the same as the intro price, and the plan lists "Flat monthly price (no intro discount)". See the price table for the current amount.

  • How is this plan billed?

    The billing is described as "USD per month equivalent; billing term and prepayment depend on plan", with a term of 1 month. Check the exact billing term and any prepayment requirement in the price table and at checkout.

  • Do I get SSH and root access?

    Yes, it is a self-managed Cloud VPS, so you administer the server over SSH. That also means updates, firewall rules and backups are your responsibility.

The DigitalOcean plans list RAM and storage only, and their billing term and prepayment depend on plan. Pick based on the resources your project needs and the billing style you prefer.
