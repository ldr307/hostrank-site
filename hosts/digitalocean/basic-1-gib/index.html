Planning a low-downtime cutover

The steps below are general practice and are not specific to this host. Lower the DNS TTL on your current records well ahead of the move, so that resolvers pick up the change quickly at cutover time.

Build and test the new server in parallel while the old one still serves traffic. Sync data, run a final sync during a short write freeze, then switch DNS records. Keep the usage-billed server running until traffic has fully drained, and only then shut it down so it stops generating charges.

The official data does not confirm whether this plan includes SSH or root access, snapshots, or a migration tool. Verify these on the provider's site before you plan the data transfer method.

Practical setup guide

  1. STEP 1Record the renewal date and renewal price

    Right after signing up, note the renewal date and the renewal price shown in the table on this page. Add both to your team's budget tracker so the move away from usage billing stays measurable. Keep the old server's final invoice for comparison.

  2. STEP 2Check current DNS and lower TTLs

    Before you change anything, confirm which nameservers your domain uses now, replacing example.com with your own domain: dig +short NS example.com. Lower the TTL on the records you plan to change and wait for the old TTL to expire. This keeps the switchover window short.

  3. STEP 3Connect the domain to the new server

    Point your DNS records at the new server, either by changing nameservers or by editing A and AAAA records with your current DNS provider. Keep the old server online until traffic stops arriving there. Then decommission it so it no longer generates usage charges.

  4. STEP 4Enable an SSL certificate and verify HTTPS

    The official data does not confirm whether an SSL certificate is included, so check with the provider before you sign up and plan how you will issue one. Once it is installed, confirm that HTTPS responds and that redirects behave as expected, replacing example.com with your own domain: curl -I https://example.com.

  5. STEP 5Confirm how backups and restores work

    The official data does not confirm whether backups or snapshots are included or billed separately. Find out what the provider offers and what it costs, and set up your own off-server backups if needed. Run a test restore before you shut down the old server.
