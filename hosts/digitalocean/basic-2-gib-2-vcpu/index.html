What the official data lists for this plan

The pricing page lists four resources for DigitalOcean Basic 2 GiB / 2 vCPU: 2 vCPU, 2 GiB of RAM, 60 GiB SSD storage and 3,000 GiB of bandwidth. The plan sits in the Cloud VPS category and is a self-managed server, which means the operating system, web server, PHP, database and WordPress itself are installed and maintained by the person who rents it.

The only listed feature is Flat monthly price (no intro discount). Nothing in the data describes a control panel, operating system images, a snapshot or backup add-on, data center locations, support channels or a WordPress installer, so anyone who depends on those should confirm them on the provider's site before paying. SSH access is the normal way to work on a self-managed server, and the practical steps on this page assume it.

How per-second billing works on this plan

Billing is listed as USD per month; billed per second up to the monthly price (capped at 672 hours a month). In practice, charges build up second by second while the server exists and stop climbing once they reach the monthly price shown in the table. The term of 1 month is the billing cycle for that cap, not a commitment to keep the server for that long.

The feature list says Flat monthly price, but the billing field describes how the charge is actually calculated, so the monthly figure is a ceiling rather than an identical charge every month. A server that exists for a full month reaches the cap; one that is destroyed partway through accrues less. The data does not say which actions, such as powering a server off, reduce or stop charges, so that should be confirmed with DigitalOcean rather than assumed.

Because there is no intro discount, the renewal price in the table is the same as the first-month price. There is no promotional rate that ends later, which keeps the arithmetic simple for anyone comparing this plan with shared hosting offers that are structured around a discounted first period.

What changes when you move WordPress off shared hosting

On shared hosting, the host keeps the server patched, runs the web server and PHP, usually takes backups and gives you a control panel for email, databases and SSL. On a self-managed Cloud VPS, every one of those tasks moves to you or to tools you set up yourself. The plan gives you a blank server with 2 vCPU, 2 GiB of RAM and 60 GiB SSD; the stack that runs WordPress on top of it is your responsibility.

The usual path is to install a web server such as Nginx or Apache, PHP, and MySQL or MariaDB, then copy the WordPress files and import the database from the old host. Email hosting is also something to plan for, since a fresh server does not come with mailboxes and the data does not mention any email service; many site owners keep email with a separate provider rather than running a mail server themselves.

The upside is control: you choose PHP versions, caching layers and server tuning instead of accepting what a shared plan allows. The trade-off is that mistakes are yours to fix, so a WordPress owner making this move should set aside time to learn basic Linux administration or budget for someone who already has it.

Security updates, a firewall and backups you now own

Security updates on a self-managed server are not automatic unless you make them so. Most Linux distributions offer an unattended-upgrades style package that installs security patches on a schedule; turning that on early is one of the simplest ways to reduce risk. WordPress core, themes and plugins still need their own updates, exactly as they did on shared hosting.

A firewall is the second item. Allow SSH, HTTP and HTTPS and block everything else by default, and consider key-based SSH login rather than passwords. None of this is provided by the plan; it is standard server work that applies to any provider.

Backups are where shared hosting habits cause the most trouble, because people assume someone else is taking them. The data for this plan does not list an included backup or snapshot feature, so plan for your own. A WordPress backup needs both the files and the database; if WP-CLI is installed on the server, the database can be exported to your home folder, outside the public web folder, with this command, replacing the path if you prefer another location: wp db export ~/backup.sql. Copy backups off the server to separate storage, and test a restore at least once so you know the procedure works before you need it.

Practical setup guide

  1. STEP 1Create the server and note its IP address

    After signing up, create the server on the DigitalOcean Basic 2 GiB / 2 vCPU plan and choose an operating system from whatever images the provider offers, since the data does not list them. Write down the server's IP address and, if one is assigned, its IPv6 address. Log in over SSH and confirm you can run commands as a user with sudo before going further.

  2. STEP 2Install the stack and move the WordPress site

    Install a web server, PHP and a MySQL or MariaDB database, then copy the WordPress files and import the database exported from your shared host. Update the database credentials in wp-config.php and test the site on the new server before changing any DNS, for example by viewing it through a temporary hosts-file entry on your own computer. Do not move visitors until the copy works.

  3. STEP 3Point the domain's A and AAAA records at the server

    In your DNS provider's settings, change the domain's A record to the new server's IP address and the AAAA record to its IPv6 address if you have one. From your own computer you can check which address the domain currently resolves to by running this command, replacing example.com with your domain: dig +short A example.com. Once it returns the new IP, traffic is reaching the VPS.

  4. STEP 4Issue a TLS certificate once DNS points at the server

    With the domain resolving to the new server, issue a Let's Encrypt certificate using Certbot or the method recommended for your web server, and enable the redirect from HTTP to HTTPS. Update the WordPress site and home URLs to use https if they do not already. Check that the padlock appears and that mixed-content warnings are gone.

  5. STEP 5Set up security updates, a firewall and backups

    Enable automatic security updates for the operating system, configure a firewall that allows only SSH, HTTP and HTTPS, and switch SSH to key-based login. Schedule regular backups of the WordPress files and database and copy them off the server, then run a restore test. Because the data does not list a backup feature or say how charges behave when a server is stopped, confirm both with DigitalOcean rather than assuming.

Frequently asked questions

  • Does the price of DigitalOcean Basic 2 GiB / 2 vCPU change after the first month?

    No. The plan has no intro discount, and the renewal price shown in the table is the same as the first-month price. The monthly figure is a cap that per-second charges build up to; it is not a promotional rate that ends later.

  • Is this a fixed monthly charge like shared hosting?

    Not exactly. Billing is listed as USD per month; billed per second up to the monthly price (capped at 672 hours a month). Charges accrue by the second and stop rising at the monthly price, so a server that exists for less than a full month costs less than the cap. The data does not say what happens to charges when a server is powered off, so confirm that with DigitalOcean.

  • Does the plan include backups, a control panel or a WordPress installer?

    None of those appear in the official data. The listed feature is Flat monthly price (no intro discount), together with 2 vCPU, 2 GiB of RAM, 60 GiB SSD and 3,000 GiB of bandwidth. Treat backups, patching and the WordPress install as your own responsibility unless the provider confirms otherwise.

  • Will 2 vCPU and 2 GiB of RAM be enough for a WordPress site?

    The data lists those resources but gives no performance figures, so there is no verified answer here. Resource needs depend on the theme, number of plugins, caching setup and traffic. Comparing against the usage reports from your current shared host is the most reliable starting point.

  • How does it differ from DigitalOcean Basic 2 GiB?

    Both plans list 2 GiB of RAM and use the same per-second billing up to a monthly price. The plan on this page lists 2 vCPU, 60 GiB SSD and 3,000 GiB of bandwidth, while DigitalOcean Basic 2 GiB lists 1 vCPU, 50 GiB SSD and 2,000 GiB of bandwidth. Read the price table for the monthly cap of each.

  • What should a shared hosting user learn before moving to this plan?

    At minimum: connecting over SSH, installing and updating packages on Linux, configuring a web server and PHP for WordPress, setting up a firewall, and taking and restoring file and database backups. The plan itself does not provide these services; they are part of running a self-managed server.
