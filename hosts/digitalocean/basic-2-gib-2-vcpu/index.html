What the DigitalOcean Basic 2 GiB / 2 vCPU plan includes

DigitalOcean lists this plan in the Cloud VPS category with 2 vCPU, 2 GiB of RAM and 60 GiB SSD storage. The listed feature is a "Flat monthly price (no intro discount)", and the term is 1 month.

No bandwidth allowance is listed for this plan in the official data, so if your WordPress site serves a lot of media or traffic, check the transfer allowance on the DigitalOcean pricing page before signing up.

Because this is a self-managed server, you have SSH and root access to configure it the way your site needs. That freedom also means no one else is applying updates or watching the server for you unless you arrange it.

Who this plan suits

This plan fits a WordPress site owner who has outgrown shared hosting and is ready to look after a Linux server, or who is willing to learn. If you are comfortable connecting over SSH, editing configuration files and keeping a routine for updates and backups, a plan with 2 vCPU and 2 GiB of RAM gives you a dedicated slice of resources rather than a shared account.

If you would rather not handle server maintenance at all, a self-managed VPS adds work compared with shared hosting. In that case, weigh the time you will spend on upkeep against the control you gain.

What changes when you manage the server yourself

Setup: shared hosting usually arrives with a web server, PHP and a database ready to go. On a VPS you choose and install that stack yourself, then create the database and copy your WordPress files and database over. Build and test the new copy of the site before you change any DNS records, so visitors keep reaching the old site until the new one works.

Security updates: the operating system, web server, PHP and database all need patches. Turn on automatic security updates where your distribution supports them, check in regularly, and keep WordPress core, themes and plugins updated as well. A firewall that only allows SSH, HTTP and HTTPS reduces what is exposed.

Backups: the official data does not confirm whether backups or snapshots are included with this plan, so check what DigitalOcean offers and whether it costs extra. Either way, keep your own copies of the WordPress database and files off the server, and practice a restore so you know the backups actually work.

Practical setup guide

  1. STEP 1Create the server and note its IP address

    Create the DigitalOcean Basic 2 GiB / 2 vCPU server with the Linux distribution you plan to use, and add an SSH key for login. Write down the server's public IP address, plus its IPv6 address if one is assigned. You will need these when you update your DNS records later.

  2. STEP 2Apply security updates and set up a firewall

    Log in over SSH and install all pending operating system updates before adding anything else. Turn on automatic security updates if your distribution supports them. Configure a firewall that allows only SSH, HTTP and HTTPS, and consider disabling password logins in favor of SSH keys.

  3. STEP 3Install the web stack and test WordPress before moving DNS

    Install a web server, PHP and a database server, then create a database and user for WordPress. Copy your WordPress files and import the database exported from your shared hosting account. Test the site on the new server, for example through a temporary hosts file entry on your own computer, while your domain still points at the old host.

  4. STEP 4Point the domain and issue a TLS certificate

    Once the new site works, update the domain's A record, and the AAAA record if you use IPv6, to the new server's IP address. Confirm the change from your own computer, replacing example.com with your domain: dig +short A example.com. After the domain resolves to the new server, issue a TLS certificate so the site loads over HTTPS.

  5. STEP 5Set up backups and test a restore

    Schedule regular backups of both the WordPress database and the site files, and copy them off the server. If WP-CLI is installed, you can export the database from the WordPress directory: wp db export backup.sql. Restore a backup to a test location at least once to confirm it works, and check whether DigitalOcean offers server-level backups for this plan before relying on them.
