Checking DNS and HTTPS from the terminal

For a static site, the two most common post-deploy problems are a domain still pointing at old nameservers and HTTPS not responding as expected. Both can be checked from your local machine without logging into the server.

The setup guide below shows one command for checking nameservers and one for checking HTTPS response headers. Replace example.com with your own domain each time.

Practical setup guide

  1. STEP 1Point your domain at the server

    Decide whether you will switch nameservers or edit DNS records at your current registrar, then make the change there. Replace example.com with your own domain, then run this from your local terminal to see which nameservers it uses now: dig +short NS example.com

  2. STEP 2Enable and verify HTTPS

    The official data does not confirm that an SSL certificate is included, so check with DigitalOcean how to set one up before signing up. Once a certificate is in place, replace example.com with your own domain and check the response headers and any redirects from your local terminal: curl -I https://example.com

  3. STEP 3Learn how backups and restores work

    The official data does not mention backups for this plan. Before you push production builds, find out whether backups are available, how often they run and how a restore is done. Keep a copy of your build output and source in your own repository as well.

  4. STEP 4Note the renewal date and renewal price

    The listed feature is Flat monthly price (no intro discount), but confirm the renewal price and term length in the verified table on this page. Add the renewal date to your calendar so the server is not interrupted unexpectedly.
