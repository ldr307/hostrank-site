What the official data lists for DigitalOcean Basic 8 GiB

The plan is listed in the Cloud VPS category with 4 vCPU, 8 GiB of memory and 160 GiB SSD storage. It is a self-managed server: DigitalOcean provides the virtual machine, and the operating system, web server, runtime, database, updates, firewall and backups are the developer's responsibility.

The only feature listed in the official data is "Flat monthly price (no intro discount)". The term is 1 month, the billing is described as "USD per month equivalent; billing term and prepayment depend on plan", and the renewal price is the same as the first-term price. The price table on this page shows the current amounts.

Sizing vCPU and memory for a web app

For a web app the useful questions are how many worker processes or threads the app runs, whether a database and a cache live on the same machine, and how much memory the runtime holds at idle versus under load. A plan with 4 vCPU gives room to run application workers alongside a database on one box, and 8 GiB leaves headroom for an in-memory cache, background job workers or a container runtime without immediately reaching for swap.

If the app is a single lightweight process with a small database, the smaller DigitalOcean Basic 4 GiB plan with 2 vCPU and 4 GiB may be enough, and the comparison section below lays out both. Memory-heavy runtimes, several containers, build or test tooling on the same server, or a database with a working set that should stay in RAM are the usual reasons to start at 8 GiB instead.

One thing the official data does not confirm for this plan is the processor family or clock speed behind the 4 vCPU. The Vultr alternatives on this page include a hardware description in their feature text; DigitalOcean's listing here does not, so a developer who needs that detail should check it with the provider before signing up.

Storage and transfer: what is listed and what is not

The 160 GiB SSD has to hold the operating system, the app and its dependencies, the database, logs and any local backups or build artifacts. Logs and user uploads tend to grow quietly, so it helps to decide early where uploads will live and to set log rotation before the first deployment rather than after the disk fills.

The official data does not list a bandwidth or transfer allowance for this plan. An app that serves media, large downloads or heavy API traffic should have that figure confirmed with DigitalOcean before signing up. By contrast, the Vultr plans in the comparison section each list a transfer figure in their data.

Billing, term and renewal

The feature text describes a flat monthly price with no intro discount, and the term is 1 month. The renewal price is the same as the first-term price, so there is no introductory rate to lose at the end of the first month; the table shows the current amount.

The billing field reads "USD per month equivalent; billing term and prepayment depend on plan". In plain terms, the plan is priced as a monthly USD amount, and how that month is charged and whether anything is paid up front can vary by plan, so confirm the exact billing arrangement at checkout. The data does not say what happens to charges if the server is powered off or deleted partway through a month, so do not assume that stopping the server changes the bill; ask the provider.

Resizing later: planning for a different server size

The official data for this plan does not describe resizing, snapshots or moving between plan sizes, so a developer cannot rely on this page for whether an in-place upgrade from DigitalOcean Basic 4 GiB to DigitalOcean Basic 8 GiB exists, whether storage can be grown, or whether a move downward is possible. Confirm those paths with DigitalOcean before choosing a starting size.

What a developer can do regardless of the provider's answer is keep the server reproducible: provisioning scripts or configuration management, container images or a documented runtime setup, and regular database dumps stored off the server. With that in place, changing size becomes a rebuild on a new server followed by a DNS change, rather than a rescue operation under load.

Practical setup guide

  1. STEP 1Create the server and record its IP address

    Sign up, create the server on the DigitalOcean Basic 8 GiB plan, choose the operating system image you want to run, and add your SSH public key so you can log in without a password. Note the public IPv4 address and, if one is assigned, the IPv6 address; you will need them for DNS. Log in over SSH, apply pending updates, and create a non-root user for day-to-day work before deploying anything.

  2. STEP 2Deploy the app, then point DNS at the server

    Install your runtime, web server and database, deploy the app, and confirm it answers on the server's IP address over plain HTTP before touching DNS. Only then set the domain's A record (and AAAA record if you have an IPv6 address) to the new server at your DNS provider. To see what the domain currently resolves to, run from your own machine, replacing the placeholder with your domain: dig +short A example.com

  3. STEP 3Issue a TLS certificate once DNS resolves to the server

    Wait until the domain resolves to the new IP address, because certificate validation needs to reach your server. Install Certbot following the Certbot instructions for your distribution, then, if your app sits behind Nginx, request and install a Let's Encrypt certificate by running on the server, replacing both placeholders with your own hostnames: sudo certbot --nginx -d example.com -d www.example.com. Afterwards, load the site over HTTPS in a browser and confirm that plain HTTP redirects.

  4. STEP 4Set up security updates, a firewall and backups

    Enable automatic security updates for the operating system and configure a host firewall that allows SSH, HTTP and HTTPS and blocks everything else by default. Schedule regular database dumps and file archives, and copy them off the server so a disk failure or a mistaken command does not take the backups with the site. The official data does not confirm a provider-side backup or snapshot option for this plan, so check with DigitalOcean whether one is offered and test a restore of your own backups either way.

  5. STEP 5Note the billing details

    The plan has a 1 month term, and the renewal price in the table is the same as the first-term price, so record the date the next month's charge falls due and keep a valid payment method on the account. Because the billing note says billing term and prepayment depend on plan, confirm at checkout exactly how this plan is charged. Do not assume that powering the server off changes the bill; the data does not say so.

Frequently asked questions

  • Is DigitalOcean Basic 8 GiB a managed server?

    No. It is listed as a Cloud VPS and is self-managed, so you install and maintain the operating system, web server, runtime, database, firewall, updates and backups yourself. SSH and root access are the normal way to work on such a server.

  • Does the price change when the plan renews?

    The official data says the renewal price is the same as the first-term price, and the feature text describes a flat monthly price with no intro discount. The term is 1 month. See the price table on this page for the amount.

  • What does "billing term and prepayment depend on plan" mean?

    The plan is priced as a USD per month equivalent, but the exact billing term and whether any amount is paid up front can vary by plan. Confirm the arrangement for this plan at checkout rather than assuming a particular pattern.

  • Can the server be resized to a larger or smaller plan later?

    The resizing section above covers this: the available upgrade and downgrade paths are not something this page can state, so ask DigitalOcean directly before you commit to a size and keep your setup reproducible so a rebuild on a new server is straightforward.

  • How does DigitalOcean Basic 4 GiB differ from the 8 GiB plan?

    Basic 4 GiB has 2 vCPU, 4 GiB of memory and 80 GiB SSD, while Basic 8 GiB has 4 vCPU, 8 GiB of memory and 160 GiB SSD. Both list a flat monthly price with no intro discount, a 1 month term and the same billing description and renewal behavior.
