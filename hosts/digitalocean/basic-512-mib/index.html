What the plan lists

The official pricing data for DigitalOcean Basic 512 MiB lists these resources: 512 MiB RAM and 10 GiB SSD storage. The plan is in the Cloud VPS category, and its listed feature is "Flat monthly price (no intro discount)". The term is given as 1 month.

The official data for this plan does not list a vCPU count, a bandwidth or transfer allowance, or the exact billing method. If your app depends on CPU-heavy work or sends a lot of outbound traffic, check DigitalOcean's pricing page for these details before signing up.

Which web apps fit 512 MiB of memory

Memory is usually the first limit a small server hits. With 512 MiB RAM, the operating system, the web server, your application runtime and any database all share the same pool. As a general guideline, this size suits lightweight workloads such as a static site behind Nginx, a small API, a personal project, a staging copy of an app, or a background worker with modest memory use.

Stacks that keep several processes in memory at once, such as an app server plus a database on the same machine, can leave little headroom at this size. If your app already uses most of its memory on a development machine, a plan with more RAM is a safer starting point.

Storage is listed as 10 GiB SSD. Leave room for the operating system, package updates, logs, uploaded media and local database files. Apps that store user uploads or keep growing databases may need a larger plan or separate storage sooner.

Planning to resize later

Many developers start small and move up as traffic grows. The official data does not describe how resizing works on this plan, so check DigitalOcean's documentation on changing plan sizes, including whether disk can be reduced again after growing it, before relying on that path.

Whatever method you use, keep your app easy to move: store configuration in files or environment variables, keep regular database exports and file archives, and document your setup steps. That way, moving to DigitalOcean Basic 1 GiB or another plan is a planned change rather than an emergency.

Practical setup guide

  1. STEP 1Create the server and note its IP address

    Create the server with the operating system your app targets and choose SSH key login if offered. Once it is running, note its public IP address, and its IPv6 address if one is assigned. You will need these for SSH access and for your DNS records.

  2. STEP 2Secure the server before deploying

    Log in over SSH, install all pending security updates, and turn on automatic security updates. Set up a firewall that allows only SSH, HTTP and HTTPS. Create a non-root user with sudo rights for day-to-day work.

  3. STEP 3Deploy the app and test it by IP

    Install your web server, runtime and database, then deploy the app and confirm it responds when you visit the server's IP address. Check memory use while the app is running to confirm 512 MiB leaves enough headroom. Keep your current hosting live until the new site works.

  4. STEP 4Point the domain at the server

    Once the app is ready, update your domain's A record, and AAAA record if you use IPv6, to point at the new server. To confirm the change has reached public DNS, run this command after replacing example.com with your domain: dig +short A example.com

  5. STEP 5Issue a TLS certificate and set up backups

    After DNS points at the server and you have installed Certbot following its official instructions, issue a certificate for an Nginx setup, replacing example.com and www.example.com with your own domains: sudo certbot --nginx -d example.com -d www.example.com. Then schedule regular database exports and file archives, and copy them off the server. Test a restore so you know your backups work.

Frequently asked questions

  • Is DigitalOcean Basic 512 MiB enough for a WordPress site?

    It depends on the site. WordPress runs PHP and a database, which together can use a large share of 512 MiB RAM. A small, low-traffic site may fit, but if you plan to run plugins, caching layers and the database on the same server, a plan with more memory gives more headroom.

  • Will the price change after the first month?

    The renewal price is the same as the intro price, and the plan is described as a "Flat monthly price (no intro discount)". The amount is shown in the price table on this page.

  • How much CPU and bandwidth does this plan include?

    These details are not listed in the pricing data used for this page. Check DigitalOcean's pricing page for the vCPU count and transfer allowance before you size your app around them.

  • How do I tell when my app has outgrown this size?

    Watch memory use, swap activity, disk space and response times under real traffic. If the app regularly runs close to its memory limit, the disk keeps filling up, or responses slow down during busy periods, it is time to plan a move to a larger plan.
