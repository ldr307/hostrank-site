What the official data lists for this plan

The official data describes Vultr Cloud Compute 8 GB / 4 vCPU with the following resources: 4 vCPU, 8 GB of memory, 160 GB SSD storage and 4 TB of bandwidth. The hardware class is listed as Regular Performance (previous-gen Intel, regular SSD).

Billing is listed as USD per month; billed hourly up to the monthly price. The term is 1 month, which is the cycle of that monthly cap. The features list a flat monthly price (no intro discount), and the renewal price is the same as the intro price, so the figure in the price table is the figure to plan around.

Because this is a self-managed server, Vultr provides the virtual machine and you handle the operating system, web server, updates, firewall and backups. That fits agencies that already run their own server tooling, and it is worth keeping in mind when estimating the hours a client project will need.

Who this plan suits

This plan suits an agency that wants a dedicated server per client rather than many sites on one shared host. With 8 GB of memory and 4 vCPU, one server can carry a client's production site and a staging copy side by side, with 160 GB SSD leaving room for uploads, database dumps and build artifacts.

The 4 TB bandwidth figure matters for client sites that serve larger media or have regular traffic campaigns. For a plain staging box that only the team and the client visit, that allowance is unlikely to be the limiting factor.

Teams that mainly spin up short-lived review environments may want to read the billing section closely, since charges accrue by the hour up to the monthly cap and the official data does not describe behavior beyond that.

How hourly billing up to the monthly price works

The billing field says USD per month; billed hourly up to the monthly price. In practice, a server that runs for a full month reaches the monthly figure shown in the price table, and a server that exists for part of a month accrues hourly charges until it hits that cap. The monthly figure is therefore a ceiling, not a fixed charge that lands every month regardless of usage.

The official data does not state what happens to charges when a server is powered off, left idle or destroyed, so do not assume that stopping a staging server reduces the bill. Confirm the exact rules with Vultr before you plan client budgets around starting and stopping servers.

Since renewal is the same as the intro price, there is no discounted first period to track and no price step to warn a client about. For agencies that pass hosting costs through to clients, that makes the monthly cap a straightforward number to quote.

Keeping access, backups and billing organized per client

Running one Vultr Cloud Compute 8 GB / 4 vCPU server per client project keeps the boundaries clear: each client gets its own IP address, its own SSH keys, its own firewall rules and its own backup schedule. If a client leaves, the server can be handed over or retired without touching anyone else's environment.

On the access side, keep a record for each server with the project name, the IP address, which team members hold SSH keys, and where the deploy credentials live. Because the server is self-managed, this record is yours to maintain, not something the provider does for you.

The official data does not list backup or snapshot features, team or sub-account access, server locations, or per-project invoicing for this plan, so confirm those with Vultr before signing up if your workflow depends on them. Until then, plan on database exports and file archives stored off the server, labeled by client, as the baseline backup routine.

How it compares with the alternatives

Vultr High Performance AMD 8 GB / 4 vCPU matches this plan on 4 vCPU and 8 GB of memory, but lists 180 GB NVMe SSD and 6 TB of bandwidth, and is described as High Performance (AMD EPYC, NVMe SSD). It is billed the same way, hourly up to the monthly price, with the same renewal as intro. An agency choosing between the two would compare the price table against whether the NVMe storage and larger bandwidth figure matter for the client's workload.

Vultr High Frequency 8 GB / 3 vCPU keeps 8 GB of memory and 4 TB of bandwidth but lists 3 vCPU and 256 GB NVMe SSD, in the High Frequency (3GHz+ Intel Xeon, NVMe SSD) class. It offers more listed storage than this plan and fewer vCPU, which can suit a client site with a large media library and modest concurrent load.

Vultr High Frequency 4 GB / 2 vCPU is the smaller option with 2 vCPU, 4 GB of memory, 128 GB NVMe SSD and 3 TB of bandwidth. It is a candidate for a staging-only box or a small client site where the lower resource tier is enough.

DigitalOcean Basic 2 GiB / 2 vCPU lists 2 vCPU, 2 GiB of memory and 60 GiB SSD, with no bandwidth figure in the official data. Its billing is listed as USD per month equivalent; billing term and prepayment depend on plan, so read its own entry in the price table rather than assuming it works like the Vultr plans. Note that DigitalOcean states memory and storage in GiB while Vultr uses GB, so compare these figures only as written.

Practical setup guide

  1. STEP 1Create the server and record its IP address

    Create a Vultr Cloud Compute 8 GB / 4 vCPU server for the client project, add the SSH keys of the team members who need access, and note the public IP address as soon as it is assigned. Record the project name, IP address and key holders in your agency's access register before anything else is configured. Log in over SSH and confirm the hostname and operating system match what you expect.

  2. STEP 2Build the site, then point DNS at the server

    Install the web server and deploy the client's site or the staging copy first, testing it against the IP address or a temporary hostname so that nothing is moved before it works. Then update the domain's A record, and the AAAA record if you use IPv6, to the new IP address; for staging, use a dedicated subdomain so client production traffic is unaffected. Confirm the change has taken effect by replacing example.com with the real domain in this command: dig +short A example.com

  3. STEP 3Issue a TLS certificate once DNS resolves

    After the domain points at the server, install Certbot following the Certbot instructions for your operating system and issue a Let's Encrypt certificate. For an Nginx setup, replace both hostnames with the client's domain and run: sudo certbot --nginx -d example.com -d www.example.com. Afterwards, load the site over HTTPS in a browser and confirm the redirect from HTTP works as expected.

  4. STEP 4Harden the server and set up backups

    Enable automatic security updates and configure a firewall that allows only SSH, HTTP and HTTPS, restricting SSH to your team's addresses if the client's policy calls for it. Schedule database exports and file archives that are copied off the server to storage you control, labeled by client and date, and test a restore before the site goes live. Keep the backup location and schedule in the same per-client record as the access details.

  5. STEP 5Record the billing details per client

    Note in the client record that this server is billed hourly up to the monthly price shown in the price table, that the cycle is 1 month, and that the renewal price is the same as the intro price. If you pass hosting costs through to the client, quote the monthly cap and keep the server labeled with the client name so each line item is easy to match. Confirm with Vultr how charges are handled for servers you stop or delete, since that is not covered in the official data.

Frequently asked questions

  • Is there a required term or a renewal step with Vultr Cloud Compute 8 GB / 4 vCPU?

    The plan is billed hourly up to the monthly price. The 1 month term in the official data is the cycle of that monthly cap, and the renewal price is the same as the intro price, so there is no discounted period that ends.

  • Can one server host a client's production site and a staging copy?

    With 4 vCPU, 8 GB of memory and 160 GB SSD, one server can run both, provided you separate them by hostname, database and user account. Many agencies prefer separate servers so that a staging change can never affect production, and the hourly billing model makes a second server a matter of the price table rather than a long commitment.

  • Does the plan include backups or snapshots?

    The official data for this plan does not confirm backup or snapshot features. Plan on exporting databases and archiving site files to storage outside the server, and confirm with Vultr whether a provider-side option exists.

  • How does this plan differ from Vultr High Performance AMD 8 GB / 4 vCPU?

    Both list 4 vCPU and 8 GB of memory and are billed hourly up to the monthly price. This plan lists 160 GB SSD and 4 TB of bandwidth in the Regular Performance (previous-gen Intel, regular SSD) class, while the AMD plan lists 180 GB NVMe SSD and 6 TB in the High Performance (AMD EPYC, NVMe SSD) class. Compare the price table against which storage type and bandwidth figure the client needs.

  • Does the official data list server locations or team accounts?

    No. Server locations, team or sub-account access and per-project invoicing are not in the official data for this plan, so confirm them with Vultr before building a client workflow around them.
