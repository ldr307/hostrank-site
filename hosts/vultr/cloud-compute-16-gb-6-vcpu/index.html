What the plan includes

The official pricing data lists Vultr Cloud Compute 16 GB / 6 vCPU with 6 vCPU, 16 GB RAM, 320 GB SSD and 5 TB bandwidth. The plan sits in the Regular Performance (previous-gen Intel, regular SSD) line, which is Vultr's label for this hardware and storage tier; the data does not include measured speeds or uptime figures, so treat the label as a product tier rather than a benchmark.

The category is Cloud VPS and the plan type is a self-managed server. In plain terms, you get a server to administer rather than a hosting account with a prepared WordPress environment. The data lists only the resources, the hardware line and the billing method; it does not confirm a control panel, a one-click WordPress installer, provider-run automatic backups or snapshots, email hosting, operating system choices or available server locations. If your migration depends on any of those, check them on the Vultr site before paying.

How billing works: hourly up to a monthly cap

Billing is listed as USD per month; billed hourly up to the monthly price. In practice, charges build up by the hour, and the monthly figure in the price table acts as the ceiling for a 1 month billing cycle. The monthly price is therefore a cap, not necessarily the same fixed charge every month.

The features note a flat monthly price (no intro discount), and the renewal price is the same as the first-month price, so there is no promotional rate that later changes. The data does not state what lowers or stops hourly charges, for example whether a powered-off server still accrues them, so confirm that detail with Vultr rather than assuming it.

What changes when WordPress leaves shared hosting

On shared hosting, the host patches the operating system, runs the web server and PHP, and typically provides backup and restore tools in a control panel. On a self-managed server all of that moves to you: choosing and installing the operating system, the web server (Nginx or Apache), PHP, a database such as MySQL or MariaDB, and WordPress itself, and then keeping every one of those layers updated.

Security also becomes your job. That means a firewall that allows only SSH, HTTP and HTTPS, SSH key logins instead of passwords, operating system security updates applied on a schedule, and WordPress core, themes and plugins kept current. The work is routine once set up, but it is ongoing, and nobody else is watching the server for you unless you arrange it.

Backups deserve particular attention. Unless you add a backup service, a self-managed server has no restore point other than the ones you create, so plan to export the WordPress database and archive the site files on a schedule and copy both somewhere off the server. Test a restore at least once before the old shared hosting account is closed.

Practical setup guide

  1. STEP 1Create the server and record its IP address

    Deploy the server from your Vultr account, choosing an operating system you are comfortable administering, and add your SSH public key during creation if the option is offered. Once it is running, write down the public IP address shown for it and confirm you can log in over SSH. Do not touch your domain's DNS yet; the old shared hosting site should keep serving visitors.

  2. STEP 2Update the system, set a firewall and install the web stack

    Apply all pending operating system updates first and enable automatic security updates following your operating system's documentation. Configure a firewall that allows only SSH, HTTP and HTTPS, and disable password logins for SSH once key access works. Then install the web server, PHP and a database, create a database for the site, and copy the WordPress files and a database export from the shared host.

  3. STEP 3Test the site, then point the domain at the new server

    Check the migrated site by temporarily mapping the domain to the new IP address in your own computer's hosts file, and fix any errors before visitors see them. Before editing DNS, see what the domain points to today: dig +short A example.com Replace example.com with your own domain, then update the A record (and the AAAA record if the server has an IPv6 address) at your DNS provider to the new server's IP address and keep the old host running until the change has propagated.

  4. STEP 4Issue a TLS certificate once DNS resolves to the server

    After the domain points at the new server, install Certbot following the Certbot instructions for your operating system. With Nginx serving the site, request and install a Let's Encrypt certificate: sudo certbot --nginx -d example.com -d www.example.com Replace both hostnames with your own, then load the site over HTTPS and make sure WordPress's site address settings use the https version so there are no mixed-content warnings.

  5. STEP 5Schedule backups and understand the hourly billing

    Set up a scheduled job that exports the WordPress database and archives the site files, copies both off the server, and keeps several generations; then restore one copy to a test location to prove it works. On the billing side, remember that charges build up by the hour up to the monthly price in the table, with a 1 month billing cycle for that cap and a renewal price that is the same as the first month. Confirm with Vultr how charges behave for servers you stop or destroy, since the data does not describe that.

Frequently asked questions

  • Is there an intro discount or a higher renewal price?

    No. The features list a flat monthly price (no intro discount), and the renewal price is the same as the first-month price. The price table shows the monthly figure.

  • Does the flat monthly price mean the same charge every month?

    Not necessarily. Billing is USD per month; billed hourly up to the monthly price, so charges accumulate by the hour and the monthly price is the cap for a 1 month billing cycle. The data does not say what reduces or stops hourly charges, so ask Vultr if that matters to you.

  • Do you have to handle security updates yourself?

    Yes. This is a self-managed server, so operating system updates, the firewall, the web server, PHP and WordPress updates are all your responsibility. Most operating systems can install security updates automatically once that is configured, but you still need to reboot and check the site after kernel updates.

  • How are backups handled?

    Nothing in the plan data describes a backup service, so plan on creating your own: export the WordPress database, archive the site files, and copy both off the server on a schedule. If Vultr offers an add-on backup or snapshot product, check it on the Vultr site, since this page cannot confirm it.

  • Can several WordPress sites run on this plan?

    The data lists resources rather than a site limit, and on a self-managed server the number of sites is up to how you configure the web server. With 6 vCPU, 16 GB RAM and 320 GB SSD, hosting several sites on one server is a common reason to pick this size over the 8 GB plans, but watch your own usage rather than relying on a general rule.
