What the plan includes

The official pricing page lists four resources for this plan: 1 vCPU, 1 GB of RAM, 25 GB SSD storage and 1 TB of bandwidth. The listed features are Regular Performance (previous-gen Intel, regular SSD) and flat monthly price (no intro discount). That is the full extent of what the data confirms about the hardware and the inclusions.

For a WordPress site, those numbers describe the whole box: the operating system, the web server, PHP, the database, WordPress itself and the backups you keep locally all share the 1 GB of RAM and the 25 GB SSD. On shared hosting the database and mail usually lived on separate systems that the host maintained; here, anything you want running has to fit inside these resources and be installed by you.

The plan is a self-managed server. The data does not mention a control panel such as cPanel, a one-click WordPress installer, managed backups, snapshots, a managed firewall, server locations or support channels, so none of those should be assumed to be included. If any of them matter to your decision, confirm them with Vultr before paying.

How billing works on this plan

The billing field reads USD per month; billed hourly up to the monthly price. In practice this means charges accumulate hour by hour and are capped at the monthly price in the table. The 1 month listed as the term is the billing cycle of that cap, not a commitment: there is nothing in the data that describes a longer period or a prepayment.

Because the price after the first month is listed as the same as the price in the first month, there is no intro discount to lose later. The features call this a flat monthly price, but the hourly billing field is the governing description: treat the monthly figure as the most a running server costs in a cycle rather than as an identical charge every month.

The data does not say what happens to charges when a server is stopped, idle or deleted. Do not assume that powering a server off reduces the bill; ask Vultr how charges are calculated for stopped or deleted servers before relying on that behavior.

What changes when you leave shared hosting

On shared hosting, the host installs and patches the operating system, PHP and the database, runs a firewall, keeps backups and usually offers a control panel. On Vultr Cloud Compute 1 GB, every one of those tasks moves to you. The first day is spent installing a web server such as Nginx or Apache, PHP, MySQL or MariaDB and WordPress, and the following months are spent keeping them updated.

Security updates are the biggest ongoing change. A shared host applies operating system patches without telling you; on a self-managed server, unattended security updates have to be enabled and checked, and the WordPress core, themes and plugins still need updating from the dashboard or with WP-CLI. A server that nobody patches is the most common way a migrated WordPress site ends up compromised.

Backups are the second change. The official data does not list a backup or snapshot feature for this plan, so plan your own routine: export the database on a schedule, archive the WordPress files, and copy both somewhere off the server. A good habit on the new server is a regular database export with WP-CLI from the WordPress folder: wp db export ~/backup.sql. Replace the file path with your own backup location and move the file off the server afterward, because a backup stored only on the 25 GB SSD disappears with the server.

The third change is the firewall. Shared hosts block unwanted traffic for you; here you should configure a host firewall that allows only SSH, HTTP and HTTPS, and consider limiting SSH to key-based logins. None of this is complicated, but it is work that did not exist on shared hosting.

Who this plan suits

This plan fits a WordPress owner who runs a single modest site, is comfortable with a terminal, and wants to learn server administration without paying for resources that a small site will not use. With 1 vCPU and 1 GB of RAM it can run a lightweight WordPress stack, and the hourly billing makes it reasonable to create a server, practice the migration, and keep it only once the site is working.

It fits less well for an owner who wants someone else to apply patches, restore backups or answer tickets about a broken plugin. Nothing in the data describes managed services, and the Regular Performance (previous-gen Intel, regular SSD) feature indicates this is the baseline tier rather than the faster tiers compared below. A site with heavy page builders, large WooCommerce catalogs or several high-traffic sites on one server may outgrow 1 GB of RAM quickly.

Finally, be honest about time. A self-managed server needs a few minutes of attention most weeks for updates and backup checks. If that is not realistic, a managed WordPress host may be the better fit even though it costs more in resources per dollar.

Common migration problems and how to approach them

The site shows the old host after switching DNS. Lower the TTL on your DNS records before the move, then wait for caches to expire; check which IP the domain resolves to from an outside network rather than trusting your own browser cache.

WordPress loads but media is missing. The uploads folder was probably not copied completely, or file permissions prevent the web server from reading it. Re-copy wp-content/uploads and make sure the web server user owns or can read the files.

Mixed-content warnings after enabling HTTPS. The database still contains links beginning with http. Update the Site Address and WordPress Address settings to https and run a search-and-replace on the database with WP-CLI rather than editing rows by hand.

The server runs out of memory under load. With 1 GB of RAM, a page cache plugin or server-level caching, a lean PHP-FPM worker count and a small swap file usually stabilize a modest site. If memory pressure continues, that is the signal that the plan is too small for the workload.

Email stops arriving. Shared hosting often included mailboxes; a self-managed server does not, and nothing in this plan's data mentions mail. Use a separate mail provider and keep MX records pointing there rather than at the new server.

Practical setup guide

  1. STEP 1Create the server and record its IP address

    Deploy Vultr Cloud Compute 1 GB with a current Linux image and SSH key authentication, then write down the public IP address. Log in over SSH, create a non-root user with sudo, and enable automatic security updates for the operating system before installing anything else. Set up a host firewall that allows only SSH, HTTP and HTTPS.

  2. STEP 2Install the WordPress stack and import the site

    Install Nginx or Apache, PHP with the extensions WordPress needs, and MySQL or MariaDB. Export the database and download the files from the shared host, upload them to the new server, and restore the database. Test the site using a temporary hosts-file entry on your computer so DNS still points at the old host while you fix broken paths or permissions.

  3. STEP 3Point the domain at the new server

    Once the site works on the new server, update the domain's A record (and AAAA record if the server has one) to the new IP address at your registrar or DNS provider. Lower the TTL in advance so the switch propagates sooner, and keep the old hosting account live until you have confirmed visitors reach the new server.

  4. STEP 4Issue the TLS certificate

    After DNS resolves to the new server, install Certbot following its instructions for your distribution. With Nginx installed, request and install a Let's Encrypt certificate: sudo certbot --nginx -d example.com -d www.example.com. Replace example.com with your own domain, then update the WordPress Address and Site Address settings to https and fix any mixed-content links in the database.

  5. STEP 5Set up backups and note the billing details

    Schedule a regular database export and a file archive, copy both off the server, and test a restore at least once so you know the procedure works. The data lists no backup feature, so this routine is yours to maintain. Note that charges build up by the hour up to the monthly price in the table and that the price after the first month is the same as the first month; confirm with Vultr how stopped or deleted servers are charged.

  • Is there a control panel like cPanel?
