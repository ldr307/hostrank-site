What the official data lists for this plan

The pricing page lists four resource figures for this plan: 3 vCPU, 8 GB of RAM, 256 GB NVMe SSD storage and 4 TB of bandwidth. The hardware description is High Frequency (3GHz+ Intel Xeon, NVMe SSD). Those are the only performance-related facts available, so this page does not claim how fast a WordPress site will load on it or how many visitors it can serve; that depends on your theme, plugins, caching and traffic pattern.

Billing is the part that is easy to misread. The plan is listed as USD per month; billed hourly up to the monthly price. In practice this means charges build up hour by hour while the server exists on your account, and they stop rising once they reach the monthly price shown in the table within the 1 month billing cycle. The monthly figure is therefore a cap, not the same fixed charge every month. The feature list also says flat monthly price (no intro discount), and the renewal price is listed as the same as the first-term price, so there is no introductory rate to lose later.

The data does not say what happens to charges for a server that is stopped but not destroyed, or whether any add-on such as extra storage or automatic backups is charged separately. Ask Vultr about those points before relying on any assumption about the final bill.

What changes when you leave shared hosting

On shared hosting the provider ran the web server, PHP and the database, patched the operating system, and usually offered a control panel with a WordPress installer and a backup tool. On a self-managed Cloud VPS such as this plan, all of that becomes your job. You receive a server with an operating system, connect to it over SSH, and build the WordPress stack yourself: a web server such as Nginx or Apache, PHP with the extensions WordPress needs, and MySQL or MariaDB. Nothing about the plan prevents you from installing a control panel of your own choosing, but the official data for this plan does not mention a control panel, a WordPress installer, specific operating system images, managed backups or snapshots, server locations, support options or a firewall feature, so treat all of those as unconfirmed and check them on the Vultr order page before signing up.

Security updates are the second change. A shared host applied operating system and web server patches without asking you. Here you decide whether to enable unattended security updates, when to reboot for kernel changes, and how to keep PHP and the database current. WordPress core, themes and plugins still update from the WordPress dashboard as before, but the layer underneath them is now yours to maintain.

Backups are the third change, and the one that catches most people after a move. Shared hosts typically kept daily copies whether you asked or not. On a self-managed server, a backup exists only if you create it and store it somewhere other than the same server. A sensible routine for a WordPress site is a database export plus an archive of the wp-content folder, copied off the server on a schedule. If WP-CLI is installed on the server, the database can be exported to your home folder, outside the public web folder, with: wp db export ~/backup.sql

Who this plan suits

This plan suits a WordPress site owner who is comfortable with a terminal, or willing to learn, and who wants resources that are not shared with other customers' sites. With 8 GB of RAM and 256 GB NVMe SSD storage it has room for a WordPress installation, a database and caching, with space left for backups and media. The 4 TB bandwidth figure is listed on the pricing page; whether it covers your traffic depends on your page sizes and visitor numbers.

The hourly billing model also suits someone who wants to rehearse a migration. You can create the server, build the stack, copy the site and test it, and the charge builds hourly up to the monthly cap rather than being a single upfront payment for the cycle. Note that the data does not state that charges stop when a server is idle or switched off, so do not plan around that without confirming it with Vultr.

It is a poor fit for anyone who expects the host to install WordPress, patch the server or restore a backup on request. None of those services appear in the official data for this plan, and a managed WordPress or shared product may be a better match if that is what you need.

Common problems during a WordPress move

The most frequent surprise is that the domain still shows the old site after you change DNS. Nameserver and record changes take time to spread, and your own computer may cache the old answer. Check which IP address the domain resolves to right now from your own machine, replacing example.com with your domain: dig +short A example.com

Mixed content warnings after enabling HTTPS usually come from hard-coded http links in the WordPress database or theme. Update the WordPress Address and Site Address settings to the https version and run a search-and-replace on the database for the old scheme. Database connection errors after the copy are almost always a mismatch between wp-config.php and the user, password or database name you created on the new server.

Keep the old shared account live until the new server has served real traffic for a while and you have taken a backup from it. Cancelling the old host before DNS has fully moved is a common cause of downtime that has nothing to do with the new provider.

Practical setup guide

  1. STEP 1Create the server and record its addresses

    Sign up, choose the Vultr High Frequency 8 GB / 3 vCPU plan and the operating system and location offered on the order page, then create the server. Write down its IP address and, if one is shown, its IPv6 address, because every later step depends on them. Log in over SSH with the credentials Vultr provides and change the default password or switch to key-based login straight away.

  2. STEP 2Build the WordPress stack and copy the site before touching DNS

    Install a web server, PHP and MySQL or MariaDB, then create a database and user for WordPress. Export the database and copy the files from your shared host, import them on the new server, and update wp-config.php with the new database details. Test the site on the new server using a temporary hosts-file entry on your own computer so the public domain keeps serving from the old host until you are satisfied.

  3. STEP 3Point the domain's A and AAAA records at the new server

    At your domain registrar or DNS provider, change the A record to the new IP address and the AAAA record to the IPv6 address if you have one. Leave the old host running during the changeover. From your own computer, confirm the public answer has switched, replacing example.com with your domain: dig +short A example.com

  4. STEP 4Issue a TLS certificate once DNS resolves to the server

    After the domain points at the new server, request a Let's Encrypt certificate with a client such as Certbot for both the bare domain and the www name, and let it configure the web server for HTTPS. Set WordPress to use the https address and redirect plain HTTP to HTTPS. Confirm that automatic certificate renewal is configured, since on a self-managed server nobody else will do it.

  5. STEP 5Set up security updates, a firewall and off-server backups

    Enable automatic security updates for the operating system and schedule reboots when a kernel update needs one. Configure a firewall that allows only SSH, HTTP and HTTPS, and check whether Vultr offers a network-level firewall, since the official data does not confirm one. Schedule a database export and a file archive, copy them to storage outside the server, and test a restore once. Note that charges build hourly up to the monthly price in the table and confirm with Vultr how a stopped server and any add-ons are charged.

Frequently asked questions

  • Does the monthly price mean the same fixed charge every month?

    No. The billing line is USD per month; billed hourly up to the monthly price. Charges build up each hour the server exists on your account and stop rising at the monthly price listed in the table within the 1 month cycle. The feature list calls this a flat monthly price (no intro discount), but the hourly wording is the one that describes how the charge accrues.

  • Is there an introductory discount that ends later?

    The feature list says flat monthly price (no intro discount), and the renewal price is listed as the same as the first-term price. Based on the official data there is no introductory rate that changes afterward.

  • Does the plan include backups, a control panel or a WordPress installer?

    None of those appear in the official data for this plan. As a self-managed server, backups, a panel and the WordPress installation are things you set up yourself unless Vultr lists them as add-ons on the order page. Check before signing up if you need any of them included.

  • Will charges stop if the server is powered off?

    The data does not say. It only states that the plan is billed hourly up to the monthly price. Ask Vultr how a stopped server is charged before relying on shutting it down as a way to control cost.

  • How does this plan differ from Vultr Cloud Compute 8 GB / 4 vCPU?

    Both list 8 GB of RAM and 4 TB of bandwidth with the same billing wording. The Cloud Compute plan has 4 vCPU and 160 GB SSD and is described as Regular Performance (previous-gen Intel, regular SSD). This plan has 3 vCPU and 256 GB NVMe SSD and is described as High Frequency (3GHz+ Intel Xeon, NVMe SSD). Which fits depends on whether you value the extra vCPU or the larger NVMe storage.

  • Is 8 GB of RAM enough for a WordPress site?

    The official data lists resources only and makes no claim about traffic capacity. Many WordPress sites run on less, and the Vultr High Frequency 4 GB / 2 vCPU alternative exists for that case. Heavier sites with many plugins, large databases or server-side caching are the usual reason to choose the 8 GB plan.
