What the plan includes

The official pricing page lists these resources for Vultr Cloud Compute 4 GB / 2 vCPU: 2 vCPU, 4 GB of RAM, 80 GB SSD storage and 3 TB of bandwidth.

The listed features are "Regular Performance (previous-gen Intel, regular SSD)" and "flat monthly price (no intro discount)". In other words, this is the Regular Performance tier, not a newer hardware tier, which is worth knowing if your API is sensitive to CPU or disk speed.

Who this plan suits

For a side project or small API, the main question is whether you want to run the server yourself. On a self-managed Cloud VPS you choose the web server, runtime, database and process manager, and you are responsible for keeping them patched and backed up.

The combination of 2 vCPU and 4 GB of RAM gives you room to run an application server, a reverse proxy such as Nginx and a small database on the same machine, which is a common layout for a hobby API or a staging environment. Whether it fits your specific workload depends on your code and traffic, so measure after deployment rather than assuming.

What a self-managed server needs from you

SSH access: you log in over SSH to install packages and deploy code. Use key-based authentication and avoid working as the root user for day-to-day tasks.

Updates: the operating system and every package you install are your responsibility. Turn on automatic security updates for your distribution and plan time for manual upgrades of your runtime and database.

Firewall: allow only the services you actually expose, typically SSH, HTTP and HTTPS, and block everything else. The official data does not mention a provider-level firewall, so plan to configure one on the server itself and check Vultr's documentation for any network-level option.

Backups: the official data does not confirm any backup or snapshot service for this plan, so check before signing up and set up your own off-server backups of your code, database and configuration either way.

Practical setup guide

  1. STEP 1Create the server and secure SSH

    Create the server, choose your Linux distribution and note the public IP address it is assigned. Log in over SSH, create a regular user with sudo rights and set up key-based authentication. Then disable password logins for SSH so only your key can get in.

  2. STEP 2Apply updates and turn on the firewall

    Install all pending operating system updates and enable automatic security updates for your distribution. Configure a host firewall that allows only SSH, HTTP and HTTPS. Confirm you can still open a new SSH session before closing the current one.

  3. STEP 3Deploy and test the app before moving traffic

    Install your runtime, database and a reverse proxy such as Nginx, then deploy your side project or API. Test it against the server's IP address so you know it works before any real users are sent to it. Keep the old host running until this step is done.

  4. STEP 4Point DNS at the server and issue a TLS certificate

    Create A records, and AAAA records if your server has an IPv6 address, that point your domain at the server's IP. Once DNS resolves to the new server, install Certbot following the Certbot instructions and, if you use Nginx, replace example.com with your domain and run: sudo certbot --nginx -d example.com -d www.example.com

  5. STEP 5Set up off-server backups

    Schedule regular exports of your database and archives of your application files and configuration, and copy them to storage outside this server. Test a restore on a fresh server so you know the backups actually work. Also keep track of your billing cycle, which is listed as a term of one month.

Frequently asked questions

  • Is Vultr Cloud Compute 4 GB / 2 vCPU managed hosting?

    No. It is a self-managed Cloud VPS. You connect over SSH and handle the operating system, software installs, security updates, the firewall and backups yourself.

  • Does the price go up after the first month?

    The renewal price is the same as the intro price, and the features describe a flat monthly price with no intro discount. The current amount is in the price table.

  • Which hardware tier is this plan on?

    The feature list says "Regular Performance (previous-gen Intel, regular SSD)".

  • Should I pick the 2 GB / 2 vCPU plan instead?

    If your API runs alone and uses little memory, Vultr Cloud Compute 2 GB / 2 vCPU lists the same 2 vCPU and 3 TB of bandwidth with 2 GB of RAM and 65 GB SSD storage. If you run a database and application together, the 4 GB of RAM on this plan leaves more headroom.

  • How do I check where my domain points before issuing a certificate?

    From your local machine, replace example.com with your own domain and run: dig +short A example.com
