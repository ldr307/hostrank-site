Who this plan suits

This plan fits agencies that want a separate, self-managed server per client or per project. With 2 vCPU, 2 GB of RAM and 65 GB SSD, it can serve as a dedicated staging environment for one client, or as the live server for a client site that your team administers directly.

Because it is a self-managed Cloud VPS, your team handles the operating system, web server, certificates, updates and security. That suits agencies with in-house sysadmin or DevOps skills who prefer full control over each client environment. Agencies that want the host to manage the server for them should look at managed hosting instead.

Giving each client project its own server also keeps access, backups and billing easy to separate: one server, one set of credentials, one line on the invoice per client.

What the plan includes

The official pricing page lists these resources: 2 vCPU, 2 GB of RAM, 65 GB SSD of storage and 3 TB of bandwidth. The listed features are "Regular Performance (previous-gen Intel, regular SSD)" and "flat monthly price (no intro discount)".

The Regular Performance label means the plan runs on previous-gen Intel hardware with regular SSD storage, as stated by the provider. When a client project calls for a specific hardware generation, compare that wording with the other plan tiers the provider lists.

Billing, term and renewal

The plan is listed with a flat monthly price and no intro discount, and the term is shown as 1 month. The renewal price is the same as the intro price, so the monthly amount in the price table is what applies from the start.

For agency bookkeeping, a flat monthly price per server makes it simpler to pass costs through to each client. Keep a record of which server belongs to which client and project so every monthly charge can be assigned correctly.

What to check before signing up

The official data covers resources, the performance label, the price model and the term. It does not confirm server locations, backup or snapshot options, firewall tools, operating system choices, uptime figures, support channels, team or multi-user account access, or IPv6 availability. Check each of these on the provider's site before committing client work to the plan.

For agency use, team access and backup options deserve a close look, since they decide how easily several staff members can work on client servers and how you recover a client site after a mistake on staging or production.

Practical setup guide

  1. STEP 1Create the server and label it per client

    Create the Vultr Cloud Compute 2 GB / 2 vCPU server and note its public IP address. Give it a name that identifies the client and whether it is staging or production. Record the IP address, access credentials and project owner in your agency's shared documentation so access stays organised per client.

  2. STEP 2Secure the server before deploying

    Apply operating system security updates and enable automatic security updates. Set up a firewall that allows only SSH, HTTP and HTTPS. Use key-based SSH login for each team member who needs access, and remove keys when someone leaves the project.

  3. STEP 3Deploy the site and point DNS

    Install your web stack and deploy the client site, then test it before changing DNS. Once the site is ready, point the domain's A record, and an AAAA record if you use IPv6, at the server's IP address. Confirm the change from your own machine with this command, replacing example.com with the client's domain: dig +short A example.com

  4. STEP 4Issue a TLS certificate

    After DNS resolves to the new server, issue a certificate. If the server runs Nginx and Certbot is installed, run this command, replacing example.com and www.example.com with the client's domains: sudo certbot --nginx -d example.com -d www.example.com

  5. STEP 5Set up backups and track billing per client

    Review the backup options the provider offers and set up a routine for each client server, keeping an off-server copy of files and databases. Test a restore on a staging server so recovery steps are proven. Finally, note the monthly charge and term for this server against the client's project so billing stays easy to pass through.

Frequently asked questions

  • Does the price change when the plan renews?

    No. The renewal price is listed as the same as the intro price, and the plan carries a flat monthly price with no intro discount. The amount is shown in the price table.

  • Is this plan managed or self-managed?

    It is a self-managed Cloud VPS. Your team is responsible for setting up and maintaining the server software, certificates, updates and security for each client project.

  • Should an agency pick the 1 vCPU or the 2 vCPU version for staging?

    Vultr Cloud Compute 2 GB lists 1 vCPU, 55 GB SSD and 2 TB of bandwidth, while this plan lists 2 vCPU, 65 GB SSD and 3 TB of bandwidth, both with 2 GB of RAM. The single-vCPU plan suits lighter staging copies; this plan suits staging or client sites that need more processing capacity.

  • What does Regular Performance mean here?

    The provider describes it as "Regular Performance (previous-gen Intel, regular SSD)". The official data gives no benchmark figures, so judge fit by testing your own client stack.
