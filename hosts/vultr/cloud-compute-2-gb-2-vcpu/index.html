Who this plan suits

The plan is a self-managed cloud server, so it suits teams that are comfortable administering Linux servers themselves: installing a web server, managing users and keys, applying updates and running backups. An agency with in-house technical staff can use one server per client or per staging environment, which keeps each project's files, credentials and costs separate.

The listed resources are 2 vCPU, 2 GB of RAM, 65 GB SSD storage and 3 TB of bandwidth. The features describe the hardware as "Regular Performance (previous-gen Intel, regular SSD)". That wording points to a standard tier rather than a high-performance one, so readers planning heavy client workloads should compare it with larger plans before deciding.

For staging, the hourly billing model described below can make it practical to spin up a server for a review cycle. The official data does not describe how charges behave when a server is stopped or deleted, so check Vultr's billing documentation before relying on that pattern.

How billing works

The billing field reads "USD per month; billed hourly up to the monthly price". In practice this means charges build up by the hour, and the monthly price in the table is the cap for a billing cycle. The listed term of "1 month" describes the billing cycle of that monthly cap, not a commitment.

The features also mention "flat monthly price (no intro discount)", and the renewal price is listed as the same as the intro price. Because billing is hourly, read that monthly figure as the maximum for a cycle rather than a fixed charge that applies every month regardless of use.

For agencies that rebill hosting to clients, it helps to record which server belongs to which client and to note the hourly accrual model in client agreements, so invoices line up with how the provider charges.

What to check before signing up

Check the price table for the monthly cap and confirm it fits each client budget. Then look at what the official data does not cover. It does not confirm a managed backup or snapshot service, available server locations, supported operating systems, or support channels, so verify each of these on Vultr's own pages before signing up.

Because the plan is self-managed, SSH and root-level administration are part of the job. Plan who on the team holds access to each client server, how keys are rotated when staff change, and where backups are stored outside the server itself.

Comparing the alternatives

Vultr Cloud Compute 2 GB has the same billing model, features and 2 GB of RAM, but lists 1 vCPU, 55 GB SSD storage and 2 TB of bandwidth. It can fit lighter staging copies where a second vCPU is not needed.

Vultr Cloud Compute 4 GB / 2 vCPU keeps 2 vCPU and 3 TB of bandwidth but lists 4 GB of RAM and 80 GB SSD storage, with the same hourly billing up to the monthly price. It fits client production sites that need more memory or space than a staging copy.

DigitalOcean Basic 2 GiB / 2 vCPU lists 2 vCPU, 2 GiB of RAM and 60 GiB SSD storage, and DigitalOcean Basic 2 GiB lists 2 GiB of RAM and 50 GiB SSD storage with no CPU figure given. Neither DigitalOcean entry lists a bandwidth figure. Their billing field reads "USD per month equivalent; billing term and prepayment depend on plan", so check DigitalOcean's pages for how that applies. Their sizes are written in GiB rather than GB, so compare them on DigitalOcean's and Vultr's own definitions rather than treating the numbers as directly equal.

None of these is a universal pick: the choice depends on whether a project needs more memory, more storage, a specific provider for client reasons, or the hourly billing model.

Practical setup guide

  1. STEP 1Create the server and record it per client

    Create the server and note its public IP address. Record the server name, IP address, client name and who holds SSH access in your agency's project notes. Clear naming keeps staging and production servers from being mixed up later.

  2. STEP 2Secure access and the operating system

    Log in over SSH, create individual user accounts with key-based login for team members, and enable automatic security updates. Configure a firewall that allows only the services the site needs, such as SSH, HTTP and HTTPS.

  3. STEP 3Deploy the site and set up backups

    Install the web stack and deploy the client site, then confirm it works on the server before any DNS change. Archive the site files regularly and copy the archive off the server, for example with: tar -czf site-backup.tar.gz public_html

  4. STEP 4Point the domain and issue a TLS certificate

    Once the site is ready, point the domain's A record, and the AAAA record if you use IPv6, at the server's IP address. Confirm the change has taken effect, replacing example.com with the client's domain: dig +short A example.com. After DNS points at the server, issue a TLS certificate and check that HTTPS loads correctly.

  5. STEP 5Track billing per project

    Note in the client's project file that the server is billed hourly up to the monthly price shown in the table. Review the list of running servers regularly so each one can be matched to an active client or staging project.

Frequently asked questions

  • Is this plan managed or self-managed?

    It is a self-managed Cloud VPS. The agency is responsible for the operating system, web server, security updates, firewall and backups.

  • How is the plan billed?

    Charges build up hourly up to the monthly price shown in the table. The "1 month" term is the billing cycle of that cap, and the renewal price is listed as the same as the intro price.

  • Does the plan include backups?

    The features do not mention backups, so set up your own backup routine per client server and confirm any provider backup options on Vultr's pages.

  • What resources does the plan list?

    2 vCPU, 2 GB of RAM, 65 GB SSD storage and 3 TB of bandwidth, on hardware described as "Regular Performance (previous-gen Intel, regular SSD)".

  • Is it suitable for client production sites as well as staging?

    It depends on the client site's needs. For projects that need more memory or storage, the Vultr Cloud Compute 4 GB / 2 vCPU plan lists 4 GB of RAM and 80 GB SSD storage with the same billing model.
