What the official data lists for this plan

The resources shown on the official pricing page are 2 dedicated CPU cores, 4 GB dedicated memory and 100 GB NVMe storage. The data lists no bandwidth figure, so anyone expecting heavy downloads or video traffic should ask hosting.com how data transfer is handled before signing up.

The feature list reads: Unlimited websites, fully managed server, emails and security included, free domain registration, and daily backups included. These are the only features the official data names, so this page does not assume anything beyond them, such as a particular control panel, a specific email client or a stated uptime figure.

The term is 12 months. Billing is described as USD per month on a 1-year term, paid upfront, which means the full year is charged at signup rather than spread into monthly payments. The renewal price is higher than the first-term price; the exact amounts are in the price table on this page.

Who this plan suits

This plan fits a business owner who wants a company website without taking on server administration. The feature wording is fully managed server, so the expectation set by the pricing page is that hosting.com handles the server itself while the owner focuses on the site, the domain and the mailboxes.

The Unlimited websites feature matters for a company that plans a main site plus separate landing pages, a careers page or a sister brand. The dedicated CPU cores and dedicated memory are listed as this plan's own resources, which is a different setup from shared hosting where resources are pooled.

It is a less natural fit for an owner who wants to pay month to month or try the service briefly. The official data lists only the 1-year term paid upfront, so the decision is effectively a commitment to a full year on day one.

How billing and renewal work

The pricing page states the price in USD per month, but the plan is sold on a 1-year term and paid upfront. In practice the card is charged for the whole 12 months at checkout. Budget for the full-year figure in the table, not the per-month figure, when planning the launch.

The renewal price is higher than the introductory price. Read both the renewal price and the term in the price table before paying, and note the renewal date somewhere the business will see it, because a renewal at the higher rate will also cover a full term.

The official data does not say whether there is a money-back window, whether the plan can be cancelled mid-term, or whether a refund is given for unused months. Those are worth asking hosting.com in writing before the upfront payment.

Domain, HTTPS, email and backups: what is confirmed

Domain: the features list free domain registration. The data does not say which domain extensions qualify, whether the domain renews free in later years, or whether the credit applies if the business already owns its domain. Confirm those points before relying on the free registration in the launch plan.

HTTPS: the features say emails and security included. The data does not spell out whether an SSL certificate is part of what is called security, so a business that needs the padlock in the browser should ask hosting.com directly how certificates are issued and renewed on this plan.

Email: the same feature confirms that emails are included, but the data gives no mailbox count, storage per mailbox, webmail details or sending limits. For a company that will run sales and support addresses, those limits decide whether the included email is enough or whether a separate email service is needed.

Backups: the features state daily backups included. The data does not describe how long backups are kept, whether restores are self-service, or whether a restore costs extra. Finding out how a restore works before anything goes wrong is a sensible early task.

What the official data does not confirm

Beyond the gaps noted above, the official data for the hosting.com 4GB Cloud Server does not mention server locations, an uptime figure, support hours or channels, the control panel used, migration help for an existing site, or whether SSH or root access is offered. None of these should be assumed from the words fully managed server.

If any of these points matters for the business, for example a server location close to customers or support available during local working hours, ask hosting.com and get the answer in writing before the upfront payment.

Practical setup guide

  1. STEP 1Register or connect the company domain

    Decide whether to use the free domain registration from the feature list or a domain the business already owns. For an existing domain, the registrar's nameservers or DNS records need to point at the new server, and hosting.com should provide the values to use. From any laptop, confirm which nameservers the domain currently uses before and after the change by replacing the placeholder with the real domain: dig +short NS example.com

  2. STEP 2Build the site before moving any traffic

    Set up the company site on the new server first, using whatever tools hosting.com provides, and check pages, contact forms and images using the preview or temporary address the provider offers. If an existing site is being moved, copy it fully and test it before changing DNS, so visitors never see a half-finished site. Only switch the domain once everything on the new server looks right.

  3. STEP 3Turn on HTTPS once the domain points at the server

    After the domain resolves to the new server, enable the certificate. The features say emails and security included, but the data does not confirm that an SSL certificate is part of that, so ask hosting.com how to issue one on this plan if it is not obvious. Confirm the site answers over HTTPS and redirects correctly by replacing the placeholder with the real domain: curl -I https://example.com

  4. STEP 4Set up business email and send a test

    Create the company mailboxes such as info, sales and support, since emails are included in the features. Send a test message from each mailbox to an outside address and reply to it, and check that the mail client on each staff device can send and receive. The data does not state mailbox limits, so confirm them if the team is likely to grow.

  5. STEP 5Confirm backups and note the billing dates

    The features state daily backups included; find out where backups are stored, how long they are kept and how a restore is requested or performed, then run through a restore of a test file if the provider allows it. Record the renewal date of the 1-year term in the business calendar, together with the renewal price shown in the price table, so the higher renewal charge is not a surprise. Keep the signup confirmation with the upfront payment amount for the company's records.
