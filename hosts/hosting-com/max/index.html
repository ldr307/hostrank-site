What hosting.com Max lists on the official pricing page

The plan is listed with three concrete items: up to 50 websites, 200 staging websites and 100 GB web space. For a store, the website allowance matters when a single account should hold the main shop plus side projects such as a landing page for a seasonal line, a wholesale catalog or a separate brand. Who this plan suits

If a business runs a main shop, a few product microsites and a test copy of each, the listed allowances of up to 50 websites and 200 staging websites leave plenty of headroom. HTTPS: the first checkout protection to confirm

A checkout page must load over HTTPS so that card details, addresses and login credentials are encrypted in transit. Payment providers and browsers treat a non-HTTPS checkout as a problem, and customers notice the warning. Because the official data for hosting.com Max does not confirm how certificates are issued, ask hosting.com before paying whether a certificate is included, whether it covers the www and non-www versions of the domain, and how it is renewed.

After the site is live, a quick way to confirm that HTTPS responds and to see whether the plain HTTP address redirects is to request the response headers, replacing example.com with the store's domain: curl -I https://example.com. A store should also force every page, not only the checkout, to HTTPS, since mixed content on a product page can block scripts that the cart depends on.

Backups and staging: protecting orders and product data

For a store, a backup is only useful if it includes the database, because orders, customer accounts and stock levels live there rather than in files. Before relying on any host backup, find out how often it runs, how long copies are kept, whether a restore can be done by the owner or only through a support request, and whether the database is included. Keep an independent copy as well, exported on a schedule that matches how many orders arrive per day.

The listed 200 staging websites are the practical way to test a theme update, a new payment plugin or a shipping-rule change without touching the live checkout. Make the change on the staging copy, place a test order there, and only then apply it to the live site. Treat staging as a testing tool, not as a backup: it is a copy taken at one moment and does not capture orders that arrive afterward.

Troubleshooting checks a store owner can run

If the shop does not appear after the domain is connected, the usual cause is that DNS still points at the old server or at the registrar's parking page. Check which IP address the domain resolves to right now, replacing example.com with the store's domain: dig +short A example.com. If the result is not the address hosting.com gave for the account, the DNS change has not taken effect yet or was entered at the wrong place.

If the checkout shows a browser security warning while the home page looks fine, the certificate may not cover the exact hostname the checkout uses, or a product image or script may still be loaded over plain HTTP. The response-header check from the HTTPS section shows whether the server itself answers correctly over HTTPS; mixed-content errors appear in the browser's developer console. If a plugin update breaks the cart, restore the previous version on the staging copy first to confirm the fix before touching the live store.

Practical setup guide

  1. STEP 1Connect the domain to the hosting account

    After signup, find the nameservers or the IP address that hosting.com assigns to the account, then update the domain at the registrar. Leave the old server running until the new site is complete, because moving DNS to an empty account takes the store offline. Confirm the change has taken effect by checking which IP address the domain resolves to, replacing example.com with the store's domain: dig +short A example.com.

  2. STEP 2Enable HTTPS once DNS points at the new server

    Issue or activate the certificate only after the domain resolves to the hosting.com account, since issuance checks the domain from the outside. Make sure the certificate covers the www and non-www hostnames and that every page, including product and cart pages, redirects to HTTPS. Place a test order to confirm the checkout loads without a browser warning.

  3. STEP 3Set up backups and a staging copy before taking orders

    Find out from hosting.com how backups run, whether the database is included, how long copies are kept and how a restore is requested. Export an independent copy of the store database on a schedule that matches the order volume. Create a staging website from the listed 200 staging websites allowance so that theme and plugin changes are tested before they reach the live checkout.

  4. STEP 4Record the billing details

    The plan is billed USD per month on a 4-year term, paid upfront, so the full 48 months are charged at signup. Write down the date the term ends and set a reminder in advance, and confirm the post-term price with hosting.com since the official data does not state one. Keep the payment method on file current so the store does not go offline at the end of the term.
